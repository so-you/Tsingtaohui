# UI 组件库与设计规范

版本：V1.1  
日期：2026-05-28  

## 1. 设计目标

1. 客户端 H5 采用购物商城风格，适合外籍船员快速浏览和下单。
2. 仓库端 H5 采用高效率作业风格，强调扫码反馈、任务状态和异常提示。
3. 管理端采用 Vue 3 + Element Plus 的中后台风格，强调密度、筛选、表格、状态和批量处理。
4. 客户端、仓库端和管理端所有页面和功能支持中文和英文切换。
5. UI 规范兼顾 375px 手机宽度和桌面管理端。

## 2. 品牌和视觉方向

### 2.1 客户端 H5

风格定位：购物商城风格，参考有赞类电商的信息组织方式，但不使用第三方品牌资产。

设计特征：

1. 首页突出商品、分类、推荐和订单状态。
2. 商品卡片包含图片、名称、规格、价格、库存和配送标识。
3. 购买按钮、加入购物车、提交订单等主操作明显。
4. 页面结构轻量，减少复杂运营后台式表格。
5. 对外籍用户保持英文文案简洁直接。

### 2.2 仓库端 H5

风格定位：移动作业工具。

设计特征：

1. 高对比状态提示。
2. 大号扫码输入框和即时反馈。
3. 任务列表信息密度高，但避免小字号堆叠。
4. 成功、失败、重复扫描、数量超出等反馈在 1 秒内可见。

### 2.3 管理端 Web

风格定位：中后台运营系统。

设计特征：

1. 使用 Element Plus 表格、表单、弹窗、抽屉、分页和标签。
2. 列表页提供组合筛选。
3. 详情页使用信息分组和时间线。
4. 风险状态使用清晰颜色和图标，不依赖颜色单独表达含义。

## 3. 色彩规范

| 用途 | 色值 | 说明 |
|------|------|------|
| 主色 | `#1677FF` | 主要按钮、链接、当前导航 |
| 成功 | `#16A34A` | 完成、同步成功、收货成功 |
| 警告 | `#F59E0B` | 匹配订单、等待、黄牌警告 |
| 错误 | `#DC2626` | 异常、红牌拦截、失败 |
| 信息 | `#0891B2` | 配送中、仓库处理中 |
| 正文 | `#111827` | 主要文字 |
| 次级文字 | `#6B7280` | 辅助信息 |
| 边框 | `#E5E7EB` | 分割线和输入框 |
| 背景 | `#F7F8FA` | H5 页面背景 |
| 卡片 | `#FFFFFF` | 商品卡、订单卡 |

颜色使用规则：

1. 客户端主操作使用主色。
2. 价格使用错误色或深色高亮，避免整页大面积红色。
3. 红牌拦截必须使用错误色和文本说明。
4. 黄牌警告使用警告色和文本说明。
5. 已完成状态使用成功色。

## 4. 字体和排版

### 4.1 H5

| 场景 | 字号 | 字重 |
|------|------|------|
| 页面标题 | 18px | 600 |
| 商品名称 | 15px | 500 |
| 正文 | 14px | 400 |
| 辅助信息 | 12px | 400 |
| 价格 | 18px | 700 |
| 主按钮 | 16px | 600 |

规则：

1. 不使用随视口宽度变化的字体。
2. 英文长词需要允许换行或省略。
3. 按钮文字不得溢出。
4. 状态标签文本保持短句，英文优先使用 1 到 3 个词。

### 4.2 管理端

使用 Element Plus 默认字体体系。表格正文建议 14px，辅助信息 12px，页面标题 20px。

## 6. 客户端 H5 页面规范

### 6.1 底部导航

底部导航固定四项：

| 菜单 | 图标建议 | 页面 |
|------|----------|------|
| 首页 | home | 首页 |
| 商品 | shopping-bag | 商品分类和列表 |
| 订单 | receipt | 订单列表 |
| 我的 | user | 个人中心、语言切换、船舶信息、扫码收货 |

规则：

1. 底部导航在主流程页面常驻。
2. 商品详情、订单确认、订单详情可保留返回按钮，底部导航根据页面空间决定是否显示。
3. 扫码收货入口放在“我的”页面，按钮文案为“扫码收货”或 “Scan to Receive”。

### 6.2 首页

内容顺序：

1. 顶部语言切换和用户入口。
2. 搜索框。
3. 运营轮播图或公告。
4. 分类快捷入口。
5. 进行中订单提示。
6. 推荐商品或常购商品。

组件：

1. `AppHeader`。
2. `SearchBar`。
3. `BannerCarousel`。
4. `CategoryGrid`。
5. `ActiveOrderCard`。
6. `ProductGrid`。

### 6.3 商品列表

布局：

1. 顶部搜索框。
2. 横向一级分类。
3. 二级分类筛选。
4. 双列商品卡片。

商品卡片展示：

1. 商品图片。
2. 商品名称。
3. 规格。
4. 价格。
5. 库存状态。
6. 可无人机配送标签。
7. 加入购物车按钮。

### 6.4 商品详情

内容顺序：

1. 商品图片。
2. 商品名称和英文名称。
3. 价格。
4. 规格、重量、体积。
5. 库存和配送限制。
6. 商品描述。
7. 底部操作栏：加入购物车、立即购买。

### 6.5 购物车

组件：

1. `CartItemCard`。
2. `QuantityStepper`。
3. `CartSummaryBar`。

规则：

1. 数量不可低于 1。
2. 超出库存时展示具体库存数量。
3. 合计栏展示金额、重量和体积。

### 6.6 订单确认

信息分组：

1. 商品清单。
2. 船舶信息：船号、船籍、IMO、MMSI。
3. 船舶代理人。
4. 收货信息：收货人、Cabin No.、联系方式。
5. 配送信息：期望送达时间、备注。
6. 费用和重量体积汇总。

主按钮：提交订单。

表单校验：

1. 必填项在字段下方显示错误。
2. 提交失败时顶部展示摘要提示。
3. 红牌拦截类错误使用错误色状态块。

### 6.7 订单列表

筛选项：

1. 全部。
2. 进行中。
3. 待签收。
4. 已完成。
5. 异常。

订单卡片展示：

1. 订单编号。
2. 状态标签。
3. 商品缩略图和数量。
4. 金额。
5. 下单时间。

### 6.8 订单详情

内容：

1. 当前状态卡片。
2. 状态时间线。
3. 商品明细。
4. 仓库处理状态。
5. 无人机配送状态。
6. 海关同步状态。
7. 收货信息和船舶信息。
8. 待签收时显示验证码收货按钮。

### 6.9 我的

内容：

1. 用户信息。
2. 语言切换。
3. 船舶信息卡片。
4. 扫码收货入口。
5. 我的订单入口。
6. 联系方式和常用资料入口。
7. 退出登录。

扫码收货流程：

1. 用户点击“扫码收货”。
2. 调用 H5 摄像头能力或输入模拟包裹码。
3. 系统识别包裹码。
4. 若订单处于待签收，完成收货。
5. 若状态不允许，展示明确原因。

## 7. 仓库端 H5 组件规范

### 7.1 扫码输入组件 `ScannerInput`

用途：

1. PDA。
2. 蓝牙扫码枪。
3. 物理扫码枪。
4. 手动输入兜底。

交互规则：

1. 页面进入后输入框自动聚焦。
2. 扫码枪回显字符后按 Enter 自动提交。
3. 成功反馈使用绿色。
4. 失败反馈使用红色。
5. 重复扫描和数量超出使用黄色。
6. 扫描结果保留最近 5 条记录。

### 7.2 任务卡片 `WarehouseTaskCard`

展示：

1. 订单编号。
2. 优先级。
3. 商品数量。
4. 库位。
5. 批次。
6. 期望送达时间。
7. 当前状态。

### 7.3 复核进度 `ReviewProgress`

展示：

1. 应扫数量。
2. 已扫数量。
3. 缺少商品。
4. 多扫商品。
5. 异常提示。

## 8. 管理端组件规范

管理端优先使用 Element Plus 组件，避免重复封装基础组件。

### 8.1 页面结构

1. 左侧菜单。
2. 顶部用户信息和语言切换。
3. 面包屑。
4. 筛选区。
5. 表格区。
6. 分页。
7. 详情抽屉或详情页。

### 8.2 通用业务组件

| 组件 | 用途 |
|------|------|
| `StatusTag` | 订单、仓库、配送、海关同步状态 |
| `SearchFilterBar` | 列表筛选 |
| `DataTable` | 业务表格封装 |
| `AuditTimeline` | 操作日志时间线 |
| `CustomsSyncPanel` | 海关同步请求、响应和重试 |
| `OrderDetailDrawer` | 订单详情抽屉 |
| `RuleFormPanel` | 表单化规则配置 |

### 8.3 表格规则

1. 默认分页 20 条。
2. 长文本使用省略和 tooltip。
3. 操作列固定右侧。
4. 高风险操作使用二次确认。
5. 导出操作必须保留审计日志。

## 9. 状态标签规范

| 状态 | 中文 | 英文 | 颜色 |
|------|------|------|------|
| PENDING_CONFIRM | 待确认 | Pending | 警告 |
| CONFIRMED | 已确认 | Confirmed | 信息 |
| WAREHOUSE_PROCESSING | 仓库处理中 | Processing | 信息 |
| PENDING_OUTBOUND | 待出库 | Outbound Pending | 警告 |
| OUTBOUND | 已出库 | Outbound | 信息 |
| IN_DELIVERY | 配送中 | In Delivery | 信息 |
| PENDING_RECEIPT | 待签收 | To Receive | 警告 |
| COMPLETED | 已完成 | Completed | 成功 |
| CANCELLED | 已取消 | Cancelled | 次级 |
| EXCEPTION | 异常 | Exception | 错误 |
| SYNC_SUCCESS | 同步成功 | Synced | 成功 |
| SYNC_FAILED | 同步失败 | Sync Failed | 错误 |
| RETRYING | 重试中 | Retrying | 警告 |

## 10. 多语言文案规范

1. 所有用户可见文案、菜单、按钮、表单、状态、校验和操作反馈必须使用 i18n key。
2. 禁止在业务组件中硬编码中文或英文。
3. 错误码由后端返回，前端根据错误码和语言渲染。
4. 中文文案短句优先，英文文案动词明确。

示例：

| Key | 中文 | English |
|-----|------|---------|
| `nav.home` | 首页 | Home |
| `nav.goods` | 商品 | Goods |
| `nav.orders` | 订单 | Orders |
| `nav.mine` | 我的 | Mine |
| `mine.scanReceipt` | 扫码收货 | Scan to Receive |
| `order.submit` | 提交订单 | Submit Order |
| `auth.register` | 注册 | Register |
| `auth.login` | 登录 | Log In |

## 11. 响应式和兼容

### 11.1 H5

1. 最小支持宽度 375px。
2. 商品列表双列展示，窄屏可降级为单列。
3. 底部固定栏不得遮挡主按钮。
4. 长英文文本必须换行或省略。
5. 图片使用固定比例容器，避免列表跳动。

### 11.2 管理端

1. 推荐最小宽度 1280px。
2. 表格列过多时允许横向滚动。
3. 详情信息使用抽屉或独立详情页承载。

## 12. 可访问性和可用性

1. 按钮、输入框、标签和图标必须有可理解文本。
2. 错误提示不能只依赖颜色。
3. H5 主操作按钮高度不小于 44px。
4. 扫码反馈必须同时展示颜色、图标和文本。
5. 加载中、空状态、失败状态都必须有明确页面反馈。
