# 研发、测试、部署和运维规范

版本：V1.1  
日期：2026-05-28  

## 1. 目标

本规范用于指导青岛汇一期 MVP 的工程落地，确保客户端 H5、仓库端 H5、管理端 Web 和后端服务在开发、测试、部署和运维中保持一致标准。

## 2. 推荐仓库结构

```text
Tsingtaohui/
  h5-client/
  warehouse-client/
  admin-console/
  backend/
  development-docs/
  prd-demo-v1/
```

说明：

1. `h5-client`：Uni-app H5 客户端。
2. `warehouse-client`：Uni-app 仓库端。
3. `admin-console`：Vue 3 + Element Plus 管理端。
4. `backend`：Spring Boot 后端。
5. `development-docs`：研发文档。
6. `prd-demo-v1`：旧 PRD、原 H5 demo、历史规格和演示工程备份。

## 6. 编码规范

### 6.1 前端

1. 使用 TypeScript。
2. 组件名使用 PascalCase。
3. 页面文件按业务模块放置。
4. API 调用统一通过 `services` 层。
5. 状态管理只存储跨页面共享状态。
6. 所有用户可见文案使用 i18n key。
7. 不在前端保存第三方接口密钥。

### 6.2 后端

1. 使用 Spring Boot 和 JDK 17。
2. Controller 只做参数接收和响应转换。
3. 业务逻辑放在 Service。
4. 数据访问放在 Repository 或 Mapper。
5. 外部系统调用通过 Client 封装。
6. 写操作使用事务边界。
7. 状态流转集中在领域服务中校验。
8. 密码使用 BCrypt、Argon2 或项目统一密码哈希算法。
9. 日志不得记录密码、JWT、接口密钥和完整敏感报文。

## 7. 测试策略

### 7.1 客户端 H5 测试

必测场景：

1. 注册成功。
2. 用户名重复注册失败。
3. 登录成功和失败。
4. 中英文切换。
5. 商品分类和搜索。
6. 加入购物车和数量调整。
7. 订单确认必填校验。
8. 自动交易订单创建。
9. 匹配订单创建。
10. 我的页面扫码收货。

### 7.2 仓库端 H5 测试

必测场景：

1. 仓库工作台统计展示。
2. 拣货扫码成功。
3. 商品扫码不匹配。
4. 重复扫描。
5. 数量超出。
6. 打包生成包裹码。
7. 海关出库红牌拦截。
8. 出库成功。
9. 键盘回显扫码输入。

### 7.3 管理端测试

必测场景：

1. 权限菜单展示。
2. 用户查询和启停。
3. 船舶信息维护。
4. 商品新增、编辑、上下架。
5. 库存调整和流水记录。
6. 订单筛选和详情查看。
7. 匹配订单人工确认。
8. 海关同步记录查看和重试。
9. 对账导出。
10. 审计日志查询。

### 7.4 后端测试

必测服务：

1. 注册登录和密码哈希。
2. 用户船舶信息保存。
3. 商品查询和上下架状态。
4. 订单金额、重量和体积计算。
5. 库存锁定、扣减和释放。
6. 自动交易和匹配订单判断。
7. 订单状态流转。
8. 海关红牌拦截。
9. 黄牌节点重试。
10. 无人机匹配。
11. 无人机回调幂等。
12. 审计日志写入。

## 8. 验收测试清单

### 8.1 用户端主流程

1. 用户注册。
2. 用户登录。
3. 切换英文。
4. 填写个人船舶信息。
5. 浏览商品。
6. 加入购物车。
7. 提交订单。
8. 查看订单详情。
9. 推进订单到待签收。
10. 在“我的”页面扫码收货。
11. 订单状态变为已完成。

### 8.2 仓库和管理端流程

1. 管理端新增商品和库存。
2. 用户下单后库存锁定。
3. 仓库端拣货。
4. 仓库端复核打包。
5. 出库前触发海关红牌同步。
6. 同步失败时阻塞出库。
7. 同步成功时允许出库。
8. 系统生成配送任务。
9. 无人机回调配送状态。
10. 用户完成签收。

## 9. 数据库迁移规范

1. 使用 Flyway 或 Liquibase 管理数据库变更。
2. 每次表结构变更必须有版本化迁移脚本。
3. 禁止手工修改测试和生产库结构。
4. 字段删除需要先下线业务引用，再执行数据库变更。
5. 枚举新增必须兼容旧数据。
6. 迁移脚本中的新表必须使用 `t_` 前缀、snake_case 和单数形式。

迁移文件命名建议：

```text
V20260528_001__create_t_user.sql
V20260528_002__create_t_product.sql
V20260528_003__create_t_order.sql
```

## 10. 安全规范

1. 密码只存储哈希值。
2. JWT 设置过期时间。
3. 管理端和仓库端必须按角色授权。
4. 接口密钥保存在服务端环境变量或配置中心。
5. 日志脱敏用户联系方式、JWT、密码、接口密钥和敏感报文。
6. 导出文件需要鉴权。
7. 海关请求和响应仅授权人员可查看。
8. 关键操作必须写审计日志。

## 11. 部署规范

### 11.1 环境

| 环境 | 用途 |
|------|------|
| dev | 研发自测 |
| test | 测试验收 |
| staging | 预发布和联调 |
| prod | 生产 |

### 11.2 配置项

后端配置必须支持按环境区分：

1. 数据库连接。
2. Redis 连接。
3. JWT 密钥。
4. 文件存储地址。
5. 海关接口地址和鉴权参数。
6. 无人机接口地址和鉴权参数。
7. CORS 白名单。
8. 日志级别。

### 11.3 发布步骤

1. 合并代码到发布分支。
2. 执行前端 lint、test、build。
3. 执行后端 test 和 package。
4. 执行数据库迁移。
5. 部署后端服务。
6. 部署静态资源。
7. 执行健康检查。
8. 执行主流程冒烟测试。
9. 记录发布版本和变更摘要。

## 12. 监控和告警

### 12.1 后端指标

1. API QPS。
2. API 错误率。
3. API 响应时间。
4. 数据库连接池使用率。
5. Redis 连接状态。
6. 海关同步成功率。
7. 海关红牌拦截数量。
8. 无人机任务派发成功率。
9. 无人机回调失败数量。

### 12.2 业务告警

1. 订单创建海关同步失败。
2. 仓库出库海关同步失败。
3. 库存扣减失败。
4. 无人机匹配失败。
5. 无人机回调超时。
6. 订单长时间停留在仓库处理中。
7. 订单长时间待签收。

## 13. 交付质量门禁

进入测试环境前必须满足：

1. 前端构建通过。
2. 后端单元测试通过。
3. 数据库迁移脚本可重复执行验证。
4. API 文档和实际接口一致。
5. 需求 P0 功能有测试用例。
6. 中英文页面、菜单、按钮、表单、状态、校验和操作反馈文案完整。
7. 关键操作审计日志可查询。
8. 红牌拦截场景通过测试。

进入生产环境前必须满足：

1. 测试环境主流程验收通过。
2. 安全配置完成。
3. 生产数据库迁移方案完成演练。
4. 回滚方案明确。
5. 运维监控和告警启用。
6. 产品、研发、测试和运营共同确认发布范围。
