# 保税仓货物上船无人机配送平台产品功能说明文档

版本：V1.0  
日期：2026-05-22  
适用阶段：一期 MVP 产品功能设计  

## 1. 产品概述

本产品面向青岛港口周边货轮及保税仓业务，提供从线上下单、保税仓履约、无人机配送、送货上船到海关数据同步的完整业务闭环。

一期优先满足保税仓货物运输场景：货轮或船员通过 H5 页面扫码下单，订单由保税仓完成拣货、复核、出库，并由无人机配送至货轮。系统实时展示订单状态，并将订单及履约节点数据同步至海关服务器。

一期不包含支付、结算、送海关查验流程。货款及服务费用由收货方和发货方在线下或既有渠道结算。

## 2. 产品目标

### 2.1 业务目标

1. 建立保税仓货物到货轮的线上下单和配送履约闭环。
2. 降低货轮用户下单门槛，通过扫码 H5 完成快速下单。
3. 支持订单状态实时追踪，提升货轮用户、仓库、运营人员的信息透明度。
4. 支持无人机型号、架次、核载质量与货物订单的自动匹配。
5. 支持订单数据实时或准实时同步至海关服务器。
6. 为后续港口周边商店接入、船员购物、运营规则配置、价格规则配置预留能力。

### 2.2 产品原则

1. H5 优先：用户无需下载 App 或小程序即可下单。
2. 流程闭环优先：先完成保税仓商品运输主链路，再扩展交易和支付能力。
3. 规则可配置：交易模式、无人机匹配、价格、配送方式等规则应支持后续运营配置。
4. 三端数据一致：客户端、仓库端、管理端基于同一订单、商品、库存、配送数据。
5. 海关同步可追溯：所有同步动作需要记录请求、响应、状态和失败重试。

## 3. 用户角色

### 3.1 货轮用户 / 船员

主要使用 H5 客户端。多数用户为外籍船员，产品应支持至少中文和英文。

核心诉求：

1. 快速进入页面并浏览商品。
2. 清楚看到商品价格、库存、配送状态。
3. 简单填写船舶和收货信息。
4. 实时查看订单配送进度。
5. 能通过扫码或验证码完成收货确认。

### 3.2 保税仓操作员

主要使用仓库端。

核心诉求：

1. 接收待处理订单。
2. 按订单完成拣货、复核、打包、出库。
3. 扫码识别商品、库位、包裹和配送任务。
4. 管理动态库存和库存占用。
5. 与无人机配送环节完成交接。

### 3.3 平台运营人员

主要使用管理端。

核心诉求：

1. 管理商品、订单、库存、无人机、配送任务。
2. 设置自动交易和匹配订单规则。
3. 处理异常订单和人工匹配订单。
4. 查看海关同步状态和失败记录。
5. 配置后续价格、投送方式、动作、机型等运营规则。
6. 按船舶代理人维度查询和导出订单对账数据。

### 3.4 无人机调度 / 配送人员

主要使用管理端或配送任务模块。

核心诉求：

1. 维护无人机型号、架次、核载质量、可用状态。
2. 查看系统自动匹配结果。
3. 对无法自动匹配的任务进行人工指派。
4. 更新配送任务状态。

### 3.5 海关系统

系统对接方，不直接操作产品界面。

核心诉求：

1. 接收订单、商品、出库、配送、签收等业务数据。
2. 返回同步结果。
3. 支持失败重试和日志追溯。

## 5. 总体业务流程

### 5.1 标准订单流程

1. 用户扫描一船一码进入 H5 页面。
2. 用户浏览商品并加入购物车或直接下单。
3. 系统通过二维码加密参数自动识别船舶、泊位、锚地和船舶代理人。
4. 用户填写收货人、舱房号、期望送达时间等少量信息。
5. 系统校验商品库存、重量、体积、配送规则。
6. 系统判断订单交易模式。
7. 自动交易订单进入自动履约流程。
8. 匹配订单进入运营匹配池。
9. 仓库接收订单并锁定库存。
10. 订单创建节点同步海关，成功后进入仓库作业。
11. 仓库拣货、扫码复核、打包。
12. 系统生成包裹信息和配送任务。
13. 系统自动匹配无人机型号、架次和配送批次。
14. 仓库出库节点同步海关，成功后允许打印出库单并激活无人机任务。
15. 仓库完成出库交接。
16. 无人机配送货物至货轮。
17. 用户扫码、验证码或人工确认收货。
18. 订单完成。
19. 各关键节点数据同步至海关服务器。

### 5.2 订单状态

订单主状态建议如下：

1. 待提交：用户尚未完成下单。
2. 待确认：订单已提交，等待系统或运营确认。
3. 已确认：订单通过规则校验或人工确认。
4. 仓库处理中：仓库正在拣货或复核。
5. 待出库：货物已复核，等待出库交接。
6. 已出库：货物已离开仓库。
7. 待装载：货物等待无人机装载。
8. 配送中：无人机配送任务执行中。
9. 待签收：货物已到达，等待收货确认。
10. 已完成：用户或收货方已确认收货。
11. 已取消：订单被用户、运营或系统取消。
12. 异常：库存、配送、同步、签收等环节出现异常。

### 5.3 海关同步状态

每个订单应单独维护海关同步状态：

1. 未同步。
2. 同步中。
3. 同步成功。
4. 同步失败。
5. 重试中。
6. 已人工处理。

海关同步失败采用黄牌警告和红牌拦截分级机制，避免保税监管货物在核心申报节点未被海关确认时继续出库或离港。

红牌拦截节点：

1. 订单创建：必须同步成功并获得海关接收确认后，订单才可进入仓库作业。
2. 仓库出库：必须同步成功并获得海关接收确认后，仓库端才可打印出库单，无人机配送任务才可激活。

黄牌警告节点：

1. 配送任务创建。
2. 无人机装载。
3. 配送中。
4. 已送达。
5. 已签收。
6. 订单异常。

黄牌节点同步失败时不阻塞履约，但必须进入管理端告警列表，并支持自动重试和人工重试。

## 6. 交易模式设计

### 6.1 自动交易

自动交易适用于标准化程度高的保税仓商品订单。

触发条件：

1. 商品属于保税仓商品目录。
2. 商品库存充足。
3. 货物总重量不超过可用无人机核载质量。
4. 货物体积符合可用无人机载荷空间。
5. 商品品类允许无人机配送。
6. 船舶位置明确。
7. 配送时间处于可服务时段。
8. 海关数据字段完整。

系统动作：

1. 自动确认订单。
2. 自动锁定库存。
3. 自动生成仓库作业任务。
4. 自动生成配送任务。
5. 自动匹配无人机型号和架次。
6. 自动推送订单节点数据至海关服务器。
7. 自动向用户展示履约状态。

### 6.2 匹配订单

匹配订单适用于需要人工或复杂规则介入的订单。

触发条件：

1. 商品超重或体积超限。
2. 需要拆分多包裹或多架次配送。
3. 船舶位置不明确。
4. 配送时间特殊。
5. 库存不足但可调配。
6. 商品来自未来接入的港口周边商店。
7. 价格、配送方式或服务动作需要人工确认。
8. 自动匹配无人机失败。

系统动作：

1. 订单进入匹配池。
2. 管理端提示运营人员处理。
3. 运营人员确认商品、价格、配送方式、无人机资源。
4. 确认后转入履约流程。
5. 用户端显示订单确认中或待匹配。

## 7. 客户端 H5 功能

### 7.1 首页

功能说明：

1. 支持一船一码扫码进入，无需注册、登录、短信验证码或邮箱验证。
2. 二维码 H5 链接携带加密船舶参数，例如 ship_token、IMO、泊位、锚地、船代等信息。
3. 系统自动识别船舶、当前泊位或锚地、关联船舶代理人。
4. 展示商品入口、订单入口、扫码入口、我的入口。
5. 支持中英文切换。
6. 展示当前船舶进行中的订单。
7. 当二维码参数过期、非法或无法识别时，进入人工补充船舶信息流程。

关键字段：

1. 当前语言。
2. 当前港口。
3. 当前船舶信息。
4. 当前泊位或锚地。
5. 关联船舶代理人。
6. 二维码 token 有效期。
7. 进行中订单数量。

免登录下单流程：

1. 扫码进入 H5。
2. 系统自动识别船舶和靠泊信息。
3. 用户选品。
4. 用户确认购物车。
5. 用户填写收货人姓名和 Cabin No.。
6. 用户提交订单。

功能说明：

1. 展示待拣货、待复核、待出库、异常订单数量。
2. 展示优先处理订单。

### 9.2 拣货管理

## 10. 无人机匹配规则

### 10.1 匹配输入

系统匹配无人机时需要读取以下信息：

1. 订单商品总重量。
2. 订单商品总体积。
3. 商品品类和配送限制。
4. 起点仓库。
5. 目标货轮位置。
6. 期望送达时间。
7. 可用无人机型号。
8. 可用无人机架次。
9. 无人机核载质量。
10. 无人机可飞距离。
11. 无人机当前状态。
12. 无人机电量。
13. 无人机是否空闲。
14. 无人机载重余量。
15. 目标 GPS 坐标。

### 10.2 匹配逻辑

基础匹配规则：

1. 商品总重量小于或等于无人机核载质量。
2. 商品总体积小于或等于无人机可载体积。
3. 配送距离小于或等于无人机可飞距离。
4. 商品品类符合无人机可配送品类。
5. 无人机状态为可用。
6. 配送时间满足无人机可调度时间。

排序建议：

1. 优先选择满足核载且载重利用率最高的机型。
2. 优先选择当前空闲且距离仓库最近的架次。
3. 优先选择历史稳定性更高的机型。
4. 同等条件下选择运营成本更低的机型。

### 10.3 匹配失败处理

匹配失败时，系统应：

1. 标记失败原因。
2. 将订单转入匹配订单池。
3. 通知运营人员处理。
4. 用户端显示订单确认中。

### 10.4 无人机黑盒系统 API 契约

一期不开发无人机飞控和航线审批系统，无人机平台作为外部黑盒硬件系统接入。平台只负责订单、包裹、配送任务、状态同步和调度指令。

最小 API 契约：

1. `GET /drones/status`：获取当前港口所有可用无人机实时状态，包括无人机 ID、型号、架次、电量、是否空闲、核载质量、载重余量、可飞距离、维护状态。
2. `POST /deliveries/dispatch`：向无人机系统发送配送任务，包括订单编号、包裹编号、包裹重量、包裹体积、起点仓库、目标船舶、目标 GPS 坐标、期望送达时间。
3. `Webhook /deliveries/callback`：无人机系统回调平台，通知任务状态，包括已接收、已起飞、已到达目标上空、已投送成功、投送失败、已返航、任务取消。

接口原则：

1. 平台不直接控制飞控动作。
2. 无人机系统负责飞行安全、航线、起降、避障、返航。
3. 平台根据无人机状态回调更新订单和配送任务状态。
4. 回调状态需要幂等处理，避免重复回调导致订单状态异常。

## 13. 非功能要求

### 13.1 实时性

1. 用户端订单状态应尽量实时更新。
2. 仓库端和管理端状态更新延迟建议控制在数秒级。
3. 海关同步可采用实时推送加失败重试机制。

### 13.2 可用性

1. H5 页面应适配手机浏览器。
2. 外籍船员使用场景下，关键流程必须支持英文。
3. 下单流程应控制在少量步骤内完成。

### 13.3 可追溯性

1. 订单状态变更需要留痕。
2. 库存变更需要留痕。
3. 规则变更需要留痕。
4. 海关同步请求和响应需要留痕。

### 13.4 扩展性

1. 商品来源需要支持从保税仓扩展到港口周边商店。
2. 交易模式需要支持从自动交易、匹配订单扩展到更多模式。
3. 配送方式需要支持从无人机扩展到人工配送、车辆配送等方式。
4. 规则配置需要支持后续运营端自主调整。
5. 商品表预留商户 ID，支持未来多商户接入时平滑扩展。

### 13.5 安全性

1. 管理端和仓库端需要登录和权限控制。
2. 用户 H5 订单详情应避免被无权限访问。
3. 海关接口调用需要鉴权。
4. 关键操作需要审计日志。
5. 一船一码的二维码 token 需要加密、防篡改、可过期、可吊销。
6. 二维码 token 只能授权访问当前船舶相关页面和订单，不能跨船访问。

## 15. 关键风险与建议

### 15.1 海关接口字段不确定

风险：海关服务器所需字段、同步频率、鉴权方式未明确。

建议：一期先抽象海关同步模块，使用可配置接口地址、鉴权参数、同步节点和同步日志，等接口规范明确后再落具体字段。

### 15.2 船舶位置不稳定

风险：货轮泊位、锚地或接收点变化会影响无人机配送。

建议：订单提交时保留人工确认机制，并在匹配订单池中处理位置不明确订单。

### 15.3 无人机自动匹配规则会持续变化

风险：运营后机型、载重、配送方式、天气、投送动作等规则会变化。

建议：一期先将关键规则参数化，后续升级为完整规则引擎。

### 15.4 H5 下单转化

风险：外籍船员操作复杂会降低下单率。

建议：采用一船一码扫码即登录机制。二维码链接携带加密船舶参数，船员扫码后自动识别船舶、泊位、锚地和船代，免注册、免短信验证码、免邮箱验证。核心下单流程控制为选品、确认购物车、填写收货人和 Cabin No.、提交订单。

### 15.5 海关核心节点未确认

风险：保税监管货物在订单创建或仓库出库节点未被海关确认时继续出库或起飞，可能形成重大合规风险。

建议：订单创建和仓库出库采用红牌拦截。同步失败或未收到海关接收确认时，系统阻止仓库作业流转、出库单打印和无人机任务激活。配送中、已送达、已签收等过程节点采用黄牌警告，可继续履约并异步重试。

### 15.6 线下结算对账困难

风险：一期不做线上支付和结算，如果订单缺少船舶代理人维度，后续财务无法判断应向哪家船代公司对账。

建议：订单必须绑定船舶代理人。二维码参数优先预置本次靠泊船代，管理端支持按船代筛选订单、导出对账单，并为后续结算系统预留字段。

### 15.7 仓库扫码效率不足

风险：仓库现场光线、网络、设备条件不稳定，完全依赖手机摄像头扫码会降低拣货、复核和出库效率。

建议：仓库端 H5 必须兼容 PDA、蓝牙指环扫码枪和物理扫描枪。复核、拣货、出库页面需要提供保持焦点的输入框，捕获扫码设备回显字符和 Enter 事件后自动完成业务校验。
