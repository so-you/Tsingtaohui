## 1. 产品概述

### 1.1 产品定位

面向青岛港口周边货轮及保税仓业务，提供「线上下单 → 保税仓履约 → 无人机配送 → 送货上船 → 海关数据同步」的完整业务闭环。一期聚焦保税仓货物运输场景，不包含在线支付与结算。

### 1.2 目标用户

| 用户角色 | 使用端 | 核心场景 |
|----------|--------|----------|
| 货轮用户 / 船员 | H5 客户端 | 扫码下单、查看商品、追踪订单、确认收货 |
| 保税仓操作员 | 仓库端 | 接收订单、拣货复核打包、出库交接 |
| 平台运营人员 | 管理端 | 管理商品/订单/库存/无人机、规则配置、海关同步监控、对账导出 |
| 无人机调度 / 配送人员 | 管理端 | 维护无人机、查看匹配结果、人工指派 |
| 海关系统 | 系统对接 | 接收业务数据、返回同步结果 |

### 1.3 一期范围

**包含：**

- H5 扫码下单（一船一码免登录 + 登录绑定船只）
- 商品目录与价格展示
- 订单提交与实时状态追踪
- 保税仓库存管理
- 仓库拣货、复核、出库
- 无人机型号 / 架次管理、自动匹配
- 自动交易与匹配订单两种交易模式
- 管理端规则配置基础能力
- 海关接口数据同步及同步日志（红牌拦截 + 黄牌警告）
- 中英文基础多语言
- 船舶代理人关联与对账数据导出
- 仓库端兼容 PDA、蓝牙扫码枪等键盘回显设备
- 无人机黑盒系统最小 API 集成契约
- 通过 ShipXY / MarineTraffic API 获取船舶停泊位置，支持人工编辑

**不包含：**

- 在线支付与线上结算
- 送海关查验流程
- 复杂商家入驻体系
- 多仓调拨
- 用户会员积分与营销活动
- 完整无人机飞控系统、航线审批系统
- 无人机硬件控制与飞行安全决策

## 2. 产品目标

### 2.1 业务目标

| 编号 | 目标 | 衡量指标（建议） |
|------|------|------------------|
| BG-1 | 建立保税仓到货轮的线上下单与配送履约闭环 | 订单从创建到签收的端到端完成率 |
| BG-2 | 降低货轮用户下单门槛 | 扫码到下单完成平均操作步骤数 ≤ 5 步 |
| BG-3 | 实现订单状态实时追踪 | 状态更新延迟 < 5 秒 |
| BG-4 | 支持无人机与订单自动匹配 | 自动匹配成功率 ≥ 80%（一期目标） |
| BG-5 | 支持订单数据实时同步海关 | 海关同步成功率 ≥ 95% |
| BG-6 | 为后续港口周边商店、支付结算等预留能力 | 预留字段与接口无回归 |

### 2.2 设计原则

| 编号 | 原则 | 说明 |
|------|------|------|
| DP-1 | H5 优先 | 用户无需下载 App 或小程序 |
| DP-2 | 流程闭环优先 | 先完成运输主链路，再扩展交易和支付 |
| DP-3 | 规则可配置 | 交易模式、无人机匹配、价格、配送方式等规则支持后续运营配置 |
| DP-4 | 三端数据一致 | 客户端、仓库端、管理端基于同一订单 / 商品 / 库存 / 配送数据 |
| DP-5 | 海关同步可追溯 | 所有同步动作记录请求、响应、状态和失败重试 |
| DP-6 | 双身份模式 | 支持一船一码免登录快速下单，也支持登录用户绑定船只复用常用信息 |

## 3. 业务流程

### 3.1 标准订单全流程

```
[用户扫码进入 H5]
       ↓
[浏览商品 → 加入购物车 / 直接下单]
       ↓
[系统自动识别：船舶、泊位/锚地、船代] ← 二维码参数 / 登录绑定 / ShipXY / MarineTraffic
       ↓
[填写收货人、Cabin No.、期望送达时间]
       ↓
[系统校验：库存、重量、体积、配送规则]
       ↓
[判断交易模式]
  ├─ 自动交易 → 自动确认 → 锁库存 → 生成仓库作业 + 配送任务
  └─ 匹配订单 → 进入匹配池 → 运营人工确认
       ↓
[海关同步：订单创建节点] ← 红牌拦截，成功后方可进入仓库作业
       ↓
[仓库拣货 → 扫码复核 → 打包 → 生成包裹]
       ↓
[系统自动匹配无人机型号、架次、配送批次]
       ↓
[海关同步：仓库出库节点] ← 红牌拦截，成功后方可打印出库单并激活无人机任务
       ↓
[出库交接]
       ↓
[无人机配送至货轮]
       ↓
[用户扫码 / 验证码 / 人工确认收货]
       ↓
[订单完成]
       ↓
[各关键节点数据同步至海关]
```

### 3.2 订单状态机

| 状态 | 编码 | 触发条件 | 可流转至 |
|------|------|----------|----------|
| 待提交 | PENDING_SUBMIT | 用户尚未完成下单 | 待确认、已取消 |
| 待确认 | PENDING_CONFIRM | 订单已提交，等待系统或运营确认 | 已确认、已取消 |
| 已确认 | CONFIRMED | 通过规则校验或人工确认 | 仓库处理中、已取消 |
| 仓库处理中 | WAREHOUSE_PROCESSING | 仓库开始拣货或复核 | 待出库、异常 |
| 待出库 | PENDING_OUTBOUND | 货物复核完成，等待出库交接 | 已出库、异常 |
| 已出库 | OUTBOUND | 货物已离开仓库 | 待装载 |
| 待装载 | PENDING_LOADING | 货物等待无人机装载 | 配送中 |
| 配送中 | IN_DELIVERY | 无人机配送任务执行中 | 待签收、异常 |
| 待签收 | PENDING_RECEIPT | 货物已到达，等待收货确认 | 已完成、异常 |
| 已完成 | COMPLETED | 用户或收货方确认收货 | —（终态） |
| 已取消 | CANCELLED | 用户 / 运营 / 系统取消 | —（终态） |
| 异常 | EXCEPTION | 库存 / 配送 / 同步 / 签收环节异常 | 已确认、仓库处理中、已取消 |

### 3.3 海关同步状态

| 状态 | 编码 | 说明 |
|------|------|------|
| 未同步 | SYNC_NONE | 尚未发起同步 |
| 同步中 | SYNCING | 请求已发送，等待响应 |
| 同步成功 | SYNC_SUCCESS | 海关返回接收确认 |
| 同步失败 | SYNC_FAILED | 同步失败 |
| 重试中 | RETRYING | 失败后自动重试 |
| 已人工处理 | MANUAL_RESOLVED | 人工介入处理完成 |

### 3.4 海关同步分级机制

| 级别 | 节点 | 行为 |
|------|------|------|
| **红牌拦截** | 订单创建 | 必须同步成功并获得海关接收确认后，订单方可进入仓库作业 |
| **红牌拦截** | 仓库出库 | 必须同步成功并获得海关接收确认后，方可打印出库单并激活无人机任务 |
| 黄牌警告 | 配送任务创建 | 不阻塞履约，失败进入告警列表，支持自动 / 人工重试 |
| 黄牌警告 | 无人机装载 | 同上 |
| 黄牌警告 | 配送中 | 同上 |
| 黄牌警告 | 已送达 | 同上 |
| 黄牌警告 | 已签收 | 同上 |
| 黄牌警告 | 订单异常 | 同上 |

## 4. 交易模式

### 4.1 自动交易（Auto-Trade）

**适用场景：** 标准化保税仓商品订单，满足全部自动条件时触发。

**触发条件（全部满足）：**

| 编号 | 条件 |
|------|------|
| AT-1 | 商品属于保税仓商品目录 |
| AT-2 | 商品库存充足 |
| AT-3 | 货物总重量 ≤ 可用无人机核载质量 |
| AT-4 | 货物体积 ≤ 可用无人机载荷空间 |
| AT-5 | 商品品类允许无人机配送 |
| AT-6 | 船舶位置明确 |
| AT-7 | 配送时间处于可服务时段 |
| AT-8 | 海关数据字段完整 |

**系统自动执行：**

1. 确认订单
2. 锁定库存
3. 生成仓库作业任务
4. 生成配送任务
5. 匹配无人机型号和架次
6. 推送订单节点数据至海关
7. 向用户展示履约状态

### 4.2 匹配订单（Matching Order）

**适用场景：** 需要人工或复杂规则介入的订单。

**触发条件（满足任一）：**

| 编号 | 条件 |
|------|------|
| MO-1 | 商品超重或体积超限 |
| MO-2 | 需拆分多包裹或多架次配送 |
| MO-3 | 船舶位置不明确 |
| MO-4 | 配送时间特殊 |
| MO-5 | 库存不足但可调配 |
| MO-6 | 商品来自未来接入的港口周边商店 |
| MO-7 | 价格 / 配送方式 / 服务动作需人工确认 |
| MO-8 | 自动匹配无人机失败 |

**处理流程：**

1. 订单进入匹配池
2. 管理端提示运营人员处理
3. 运营确认商品、价格、配送方式、无人机资源
4. 确认后转入履约流程
5. 用户端显示「订单确认中」或「待匹配」

## 6. 无人机匹配规则

### 6.1 匹配输入

| 类别 | 字段 |
|------|------|
| 订单信息 | 商品总重量、商品总体积、商品品类和配送限制 |
| 位置信息 | 起点仓库、目标货轮位置、目标 GPS 坐标 |
| 时间信息 | 期望送达时间 |
| 无人机信息 | 可用无人机型号、架次、核载质量、可载体积、可飞距离、当前状态、电量、是否空闲、载重余量 |

### 6.2 匹配逻辑

**基础规则（全部满足）：**

| 编号 | 规则 |
|------|------|
| MR-1 | 商品总重量 ≤ 无人机核载质量 |
| MR-2 | 商品总体积 ≤ 无人机可载体积 |
| MR-3 | 配送距离 ≤ 无人机可飞距离 |
| MR-4 | 商品品类符合无人机可配送品类 |
| MR-5 | 无人机状态为「可用」 |
| MR-6 | 配送时间满足无人机可调度时间 |

**排序规则（优先级从高到低）：**

1. 载重利用率最高（满载优先）
2. 当前空闲且距离仓库最近
3. 历史稳定性更高
4. 运营成本更低

### 6.3 匹配失败处理

1. 标记失败原因
2. 订单转入匹配订单池
3. 通知运营人员处理
4. 用户端显示「订单确认中」

### 6.4 无人机黑盒系统 API 契约

一期无人机平台作为外部黑盒硬件系统接入。平台只负责订单、包裹、配送任务、状态同步和调度指令，不直接控制飞控。

**最小 API 契约：**

| API | 方法 | 说明 | 关键参数 |
|-----|------|------|----------|
| `/drones/status` | GET | 获取所有可用无人机实时状态 | 无人机 ID、型号、架次、电量、空闲状态、核载质量、载重余量、可飞距离、维护状态 |
| `/deliveries/dispatch` | POST | 向无人机系统发送配送任务 | 订单编号、包裹编号、包裹重量 / 体积、起点仓库、目标船舶、目标 GPS、期望送达时间 |
| `/deliveries/callback` | Webhook | 无人机系统回调通知任务状态 | 已接收、已起飞、已到达目标上空、已投送成功、投送失败、已返航、任务取消 |

**接口原则：**

- 平台不直接控制飞控动作
- 无人机系统负责飞行安全、航线、起降、避障、返航
- 平台根据无人机状态回调更新订单和配送任务状态
- 回调状态必须幂等处理，避免重复回调导致订单状态异常

## 9. 非功能需求

### 9.1 性能

| 指标 | 要求 |
|------|------|
| H5 页面首屏加载 | ≤ 3 秒（4G 网络） |
| 订单状态更新延迟 | ≤ 5 秒 |
| 仓库端扫码反馈 | ≤ 1 秒 |
| 海关同步单次请求超时 | ≤ 10 秒 |
| 并发订单提交 | 支持 ≥ 100 QPS |

### 9.2 可用性

| 指标 | 要求 |
|------|------|
| H5 页面适配 | 手机浏览器，最小宽度 375px |
| 多语言 | 关键流程支持中文和英文 |
| 下单步骤 | 免登录模式 ≤ 6 步 |
| 仓库端设备兼容 | PDA、蓝牙指环扫码枪、物理扫描枪（键盘回显） |

### 9.3 可追溯性

| 数据类型 | 要求 |
|----------|------|
| 订单状态变更 | 每次变更记录时间、操作人、变更前状态 |
| 库存变更 | 每次变更记录原因、数量、操作人 |
| 规则变更 | 每次变更记录变更内容、操作人 |
| 海关同步 | 每次同步记录请求、响应、状态 |

### 9.4 扩展性

| 扩展方向 | 预留设计 |
|----------|----------|
| 商品来源 | source 字段 + merchant_id，支持从保税仓扩展到港口周边商店 |
| 交易模式 | trade_mode 枚举可扩展 |
| 配送方式 | 预留 delivery_type 字段，支持从无人机扩展到人工 / 车辆配送 |
| 规则配置 | 一期表单化，后续可升级为规则引擎 |
| 多商户 | 商品表预留 merchant_id |

### 9.5 安全性

| 安全要求 | 说明 |
|----------|------|
| 管理端和仓库端 | 登录和权限控制 |
| H5 订单详情 | 避免无权限访问 |
| 海关接口调用 | 鉴权（API Key / Token） |
| 关键操作 | 审计日志 |
| 二维码 token | 加密、防篡改、可过期、可吊销、不可跨船访问 |

## 11. 风险与应对

| 编号 | 风险 | 影响 | 应对措施 |
|------|------|------|----------|
| R-01 | 海关接口字段不确定 | 同步模块无法落地 | 一期先抽象海关同步模块，使用可配置接口地址 / 鉴权参数 / 同步节点，等接口规范明确后落具体字段 |
| R-02 | 船舶位置不稳定 | 无人机配送目标不准确 | ShipXY / MarineTraffic 获取候选位置 + 人工编辑确认 + 记录位置来源和变更历史 |
| R-03 | 无人机匹配规则持续变化 | 硬编码导致频繁改版 | 关键规则参数化，后续升级为规则引擎 |
| R-04 | 外籍船员操作复杂降低下单率 | 用户流失 | 一船一码免登录 + 核心流程 ≤ 6 步 + 中英文支持 |
| R-05 | 海关核心节点未确认即出库 | 保税合规风险 | 订单创建和出库红牌拦截，同步失败时阻塞仓库作业和无人机任务激活 |
| R-06 | 线下结算对账困难 | 财务无法归集 | 订单必绑船舶代理人，管理端按船代筛选和导出对账单 |
| R-07 | 仓库扫码效率不足 | 仓库作业瓶颈 | 兼容 PDA / 蓝牙扫码枪 / 物理扫描枪，页面提供焦点输入框 + Enter 自动校验 |
| R-08 | 第三方船位 API 不稳定 | 位置数据缺失或延迟 | 第三方数据仅作候选，支持人工编辑确认，记录 API / 人工 / 实际位置差异 |
